# ADR-024：分层导航、管理员身份和供应商连接中心（设计）

## 决策背景
原型 Web 采用项目聊天室三栏布局，但项目右侧详情页同时承载组织管理及系统 AI。截图显示右侧狭窄表单导致过长滚动、项目工作与平台配置混用。用户要求采用类似微信桌面版的最左功能切换，但不复制其品牌或聊天专属交互。

## 信息架构
全局图标导航（首列）：**项目协作 / 组织管理（仅组织管理员） / 系统管理（仅系统管理员） / 个人设置**。
- 项目协作：第二列项目列表和新建入口；主区域聊天室；可收合右侧**项目工作面板**仅显示任务、AI 待确认、汇报、项目设置。切换项目清理当前项目数据；无权限时不显示可写控件。
- 组织管理：第二列为可管理组织列表；主区域全宽的组织成员、部门、项目集、组合和资源管理。项目列表、聊天和右侧项目面板在此视图不出现。
- 系统管理：第二列为配置导航（当前模型供应商中心）；主区域全宽供应商连接与其模型配置；不显示项目工作面板。
- 个人设置：显示当前账户信息、角色提示及退出登录。禁止将密码、全局 API Key 当作普通项目偏好。
- 所有导航遵循语义 button、焦点/键盘支持，移动端底部导航及主区域纵向布局；Tab 是否可见与后端鉴权相互独立。

## 系统管理员身份
权限标识统一称「系统管理员」，英文 System Administrator。所有用户使用同一个登录/会话；组织 admin、项目 owner 不等于系统管理员。
现有本机 `npm run admin:grant -- --email=... --confirm` 负责首次特权初始化，初始安装在无管理员时必须显式提示部署运营人员执行；不能默认注册用户自动获得权限，不提供无验证的公网升级入口。将来安装向导需要本机单次引导令牌/本机认证与后端原子一次性提升。系统管理员拥有模型平台配置权限，但不会天然继承跨组织聊天读取权限。权限撤销和全设备会话撤销是后续单独安全议题。

## 供应商与模型两层实体
- `ai_provider_connections`：连接名称（例如「公司模型代理」）、服务端 Base URL、协议适配器、服务端 AES-GCM 密文 API Key、启用状态。URL 不应是供应商官网，UI 提供独立的「官网（仅说明资料，可选）」文字时与请求 Base URL 区分；当前不保存官网，因为不是业务必需。
- `ai_model_configs`：所属供应商连接、展示名称、实际请求 model ID、Token/字符预算、推理参数映射、启用/默认状态。一个供应商可连接多个模型；默认指向一条已启用模型且所属连接也必须可用。
- `MODEL_ENCRYPTION_KEY` 是**系统启动的根密钥**，保留在安全环境/密钥管理服务中而不是 Web 界面，也不回传/导出；具体供应商的 API Key 不再写 `.env`。
- API 中只返回 `hasKey`，写入新 Key 使用仅写敏感表单；更新其他字段时不更改原 Key；不打印请求体或明文密钥。管理员变更有数据库审计。
- 确定性协议：`responses` 和 `chat-completions` 当前支持；Anthropic Messages 等协议在专门适配并实测前明确不支持。不能因 Base URL 中包含 DeepSeek/OpenAI 等品牌字符串而选择请求字段。
- 动态模型列表发现不通用，首发允许管理员手动添加模型，不捏造上下文或推理能力。测试连接采用受限请求，错误体不回传，默认 30 秒限频。
- URL 服务器端校验并拒绝重定向和不可信目标；DNS/代理重新绑定/出站网络白名单仍需要生产级加固。本机/容器本地服务访问需明确部署信任边界。

## 安全及失败行为
无默认模型、连接禁用、密钥错误、密文无法解密 → 模型调用失败并清晰告知管理员；不能静默回退不受授权的另一提供商。删除供应商若有关联模型应拒绝或要求管理员先移除模型，确保配置关系可解释。模型密钥与 SESSION_SECRET 生命周期分离。服务器日志与审计记录不存原始 Key。

## 非目标和取舍
本次不引入微服务、通用网络代理、自动爬取厂商模型目录、SaaS 自助付款、完整个人跨项目汇总；优先把已经存在的组织和平台配置功能置于正确的页面。不维护旧的项目级提供商设置接口。现有数据库连接数据通过一次性迁移尽量保留，但无需保留旧 API/页面逻辑。

## 验收
- 使用普通统一入口登录；仅被授权的系统管理员在首列看到系统管理；后端对伪造请求依旧 403。
- 项目右侧无公共管理标签，组织与系统管理主区域宽度可使用且可操作；键盘与窄屏可达。
- 不修改 .env 的大模型字段即可在后台创建供应商、保存 Key、添加模型、设置默认、测试连接；所有读取接口不回传 Key。
- 供应商与模型分离，多模型共用连接凭据；禁止未知协议/供应商名称猜测；迁移运行可重复。
- 跨项目/组织读写保持受控，单条有效默认模型，事务审计；所有 PR 门禁通过。

## ADR-025 · 供应商创建显式状态与移动端导航（2026-10-14）

- 管理员从已选中连接点击「添加供应商」后，进入**可辨认的创建状态**：现有连接不得仍高亮为当前编辑对象；清空表单，显示「正在新建」提示，将焦点移动到连接名称字段。取消创建应返回已选连接而非静默丢失输入。成功保存后的服务端提供商 ID 决定选中状态。
- 移动端采用同一项目下互斥的「消息」和「工作台」视图；避免将聊天、表单、报告长列堆叠成必须上下滚动的大页面。项目切换应回到消息视图，保留权限控制。桌面继续三/四栏布局。
- ChatPM 品牌统一复用应用 `/icon.svg`（对应 `assets/brand/mark.svg` 的聊天气泡勾选图形）；仅 AI 消息可采用辅助符号；不能以字体字符充当全局商标。
- 异步请求失败显示可操作错误；创建或保存不以仅凭状态重置暗示成功。基本验收：已有一个供应商时添加按钮必定显示空表单和焦点、保存后自动选择新供应商、手机 375px 能切换消息/任务、Logo 与 favicon 同源。
