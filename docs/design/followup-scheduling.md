# 主动跟进、提醒与风险升级

## 当前运行规则

跟进计划 `FollowUpPlan` 持久化在 PostgreSQL；独立 Worker 领取到期任务，检查最新任务版本、正式负责人、截止时间及项目提醒策略。**只有任务具有负责人和期限，且项目配置了合法工作时间与冷却间隔时，才启用提醒。**

Worker 当前通过站内 AI 消息提醒，不依赖 Redis/BullMQ。完成和取消的任务停止跟进，重新分配/改期不绕过已发送提醒的冷却期限。重复 nonce 不产生两次站内消息与发送审计。

## 工作时间和下一次检查

- 按项目 IANA 时区与周一至周五、配置的本地起止小时判定提醒资格。
- 到期检查时如处于静默/周末，不视为已经发送；安排到**最早合法工作窗口**，不错误消耗一个冷却周期。
- 成功创建提醒消息后才以配置冷却小时计算下次最早发送时间，再对齐下一个合法窗口。
- 支持 DST 和半小时、45 分钟偏移等时区；用纯函数测试跨天、周末和时区边界。
- 企业节假日、个人休假、非整小时工作时段尚未支持。

## 目标扩展策略

| 情况 | 目标行为 |
|---|---|
| 期限接近、尚未完成 | 合并重复问题，提醒正式负责人 |
| 任务已逾期 | 追问原因、阻塞和预计完成时间，并按授权策略升级 |
| 成员回答含糊 | 追问验收和明确承诺，不自行认定完成 |
| 依赖阻塞 | 关联已有任务与负责人，保留来源证据 |
| 长期未答复 | 冷却、合并、升级并记录干预状态 |
| 管理决策 | 生成待确认决策项，由授权人批准 |

这些目标不能被当前简单的站内提醒实现等同为已交付。

## 异步可靠性与运维

Outbox 使用 PostgreSQL 原子领取、UUID claim token、五分钟租约、最多八次尝试、指数退避、死信隔离与项目 Owner 审核重放。保存安全错误码而不是客户原文；项目负责人可以查看等待与隔离诊断。按项目每日 AI 调用次数达到上限时延迟到下一天，不因预算耗尽消耗普通重试次数。

至少一次投递不等于模型或外部通知的 exactly once。未知 Outbox 类型必须显式失败，不得静默确认。长期任务租约心跳、外部报警、重放影响评估、完整节假日策略和故障演练仍是生产门槛。

## 验收

完成、取消、版本变化、重复消息、静默时间、跨周末、夏令时、异常重启和并发 Worker 均需可复现测试。任何新通知渠道必须保留业务幂等键和项目权限。

## 提醒与 AI 拆分（ADR-021）
项目设置明确分为「AI 助手」与「自动任务提醒」两个区域。规则式任务提醒不依赖 LLM，也不以“AI 推理”名义描述；工作时间用项目时区的整点（开始包含、结束不包含，周末跳过）；冷却小时是同一正式任务最短再次提醒间隔，只有有有效负责人/期限/完整策略的未完成任务生效。界面提供“不开启提醒”的明确开关与默认建议 09:00–18:00 / 24 小时（不偷偷改变存量项目）。
