# 安全、隐私、性能与运行治理

## 权限模型
支持组织/租户、项目、成员角色和可单独授权的管理员操作。每次查询和命令都在服务器端验证租户、项目、角色及对象所属关系。群聊内容、附件索引、AI 引用遵守同一数据作用域。

## AI 特有风险
- **提示注入**：聊天消息与文档只是数据，不得覆盖平台策略；模型工具不开放原始数据库操作。
- **越权与误操作**：结构化候选必须先经策略与领域命令验证，高影响操作由人审查。
- **隐私**：定义模型供应商数据传输策略、密钥保管、敏感数据处理、数据留存与删除流程；不可默认把业务对话发给未经授权的第三方。
- **幻觉**：关键状态只来自正式记录，不确定内容需标识或询问，不作为确定结论对外发布。

## 运维与可靠性
任务处理至少一次，出错重试、隔离队列、人工重放；设置队列滞留和失败告警、模型预算、请求超时、速率限制、日志脱敏及备份恢复。

## 建议监控指标
消息入库/推送延迟、AI 候选接受率、误提取修正率、提醒重复率、逾期无人响应时长、报告引用缺失率、模型用量和成本、队列失败及重试。

## 非功能基线
MVP 先定义可实际测量的性能和可靠性目标，进行负载、数据恢复和权限测试；不在缺乏流量依据时承诺虚构的 SLA 或吞吐数字。

## 默认安全决策
当前必须由部署者配置服务端模型密钥、且项目 Owner 显式启用后，才会向第三方模型发送该项目消息；尚无独立的组织管理员模型许可机制。未配置模型时不得伪装为已完成 AI 分析。供应商权限、数据留存、费用预算和组织级策略属于后续治理目标。所有模型上下文必须按项目权限过滤。

## MVP 安全限制
会话 HttpOnly、Origin 校验、项目成员权限、模型 opt-in、基础请求限速已实现；仍需生产环境 HTTPS/可信代理部署、分布式限速、权限与提示注入集成测试、数据删除/留存、预算和外部供应商治理，未经上述验证不可上线敏感项目。

## 异步与模型安全补充
隔离事件仅项目 owner 可通过 API 查看和重放，并强制项目作用域、事件状态和审计。处理错误不能在数据库中保留异常原文、私密信息或模型输出。项目模型每日请求数限额不等于 Token 费用预算；生产发布仍需数据隐私、完整攻击测试、删除和备份恢复演练。

诊断统计端点同样需要 owner 权限，避免成员通过失败数推断其他项目的操作；队列监控当前为按需查询界面，尚无主动外部报警。
## 会话与项目隔离约束

- 创建项目时明确提供所属租户，必须检查操作者具备该租户管理员身份。
- 每个会话由带 JTI 的签名令牌与服务端 sessions 表共同校验；退出登录撤销会话。后续仍需补齐管理员全设备撤销和定期清理。
- 项目 Owner 可删除普通项目成员；权限检查必须每次访问时进行，不应缓存撤销前的角色。
- 任务、证据和消息的相互引用必须保持项目归属一致，数据库使用组合外键实现最后一道约束。
- SaaS 的组织策略、模型本地化、完整数据删除和备份恢复仍属生产验收缺口。

项目级授权校验同时要求有效的 `project_members` 与对应租户的 `tenant_members`，防止租户成员关系撤销后仍因残留项目成员记录获得访问资格。跨项目来源引用由复合外键独立约束。

## 成员撤销与任务关系

移除普通项目成员前必须先处理其未完成任务；否则拒绝移除（HTTP 409），防止持续催办已无权访问的用户。移除时对成员关系加数据库行锁，任务创建和重新指派对同一成员关系加 Key Share 锁，避免撤销与新指派并发时产生悬空业务负责人。已完成任务保留历史负责人记录。

状态更新在事务内重新验证操作人的项目成员资格；已完成任务可以保留历史负责人，但重新开启未完成任务时必须再次验证其负责人仍属于项目，避免撤权后的并发状态更新重新激活提醒。

## ADR-045 · 死信恢复与运维授权边界

在管理员确认外部模型错误已修复后，项目 owner 可以对该项目尚未处理的 dead-letter Outbox 事件发起人工重试。服务端必须在写事务内重新查组织/项目权限并为同一管理意图持久化 UUID 回执，防止网络中断后的重复点击导致多次恢复。只在 dead_at 非空且 processed_at 为空时清除 attempts/dead_at/claim 与错误码，重排 next_attempt_at，交回既有至少一次投递 Worker；成功响应不等于下游已经处理成功。失败或跨项目请求不能记录虚假“已恢复”事件。操作审计只保存项目、操作者、事件 ID 与先前尝试次数，不持久化敏感模型响应正文；Outbox 模型授权撤销和 quota 继续由真正 Worker 执行。

人工恢复使用原 `outbox_events.manual_retry_revision` 严格递增的独立版本，单次成功恢复返回 `recoveryRevision`。一次真正的新 dead→pending 恢复产生相应版本的领域事件；如果同一事件之后再次失败、再次由人恢复，新恢复使用下一个版本，避免把多次运维操作错误地全部记为 v1。

## ADR-050 · 备份演练的安全约束

禁止测试脚本覆盖正式项目数据库：必须同时检查 CI=true 与显式演练标志，且运行中不可有写入的 Web、API、Worker 服务。目标随机命名为 chatpm_restore_drill_*，数据库只可由本进程确认创建后才清理。私人备份目录 0700、备份文件 0600，无论通过或失败都进行 finally 清理。哈希检查仅输出表名/行数/哈希，不输出敏感源数据。该校验是在有限测试样本上的恢复证明，不替代外部加密、保留与删除、PITR、真实生产数据迁移和恢复时限验收。

## ADR-080 · 不掩盖 AI/Outbox 通道失败的健康判定

私有 Doctor 读取 `worker_health` 的三条 lane 快照，不读取任何项目聊天正文、API Key 或上游异常详细信息；输出有限错误码、时间与队列计数。任意通道缺失、最后一次失败未恢复、心跳/成功超时，即使另外两条 lane 正常也判定失败并设置非零退出。Linux 5 分钟 timer 和 Windows LocalService task 负责执行频率；必须额外接可信告警平台监控任务结果及计划任务自身停跑，不得把本地 JSON/日志误称为远程通知。真正公网出口、值班路由、升级/静默阈值和跨机恢复留在生产验收。

## ADR-082 · Docker 网关服务防止私网 DNS 冒充

对于 `host.docker.internal` 本地模型，`MODEL_DOCKER_GATEWAY_IPS` 是运维审查过的 1–4 个确切 RFC1918/ULA IP 的唯一信任锚；默认无配置即 fail closed。完整 DNS A/AAAA 中存在任一不同 IP、外网、回环、元数据或非法族别，整个模型出站请求失败，Bearer Key 不会发送到其它内网机器。Node HTTP(S) 仍然连接已校验固定 IP，不跟随重定向或环境代理。验证前先在实际 API/Worker 容器检查别名与宿主机网关是否真实一致；网络重建后必须重新核验，禁止为“恢复可用”放行整个私网。外部 egress ACL、网段隔离、日志脱敏、证书、QNAP/IPv6 与真实出站流量攻防测试仍属发布阻断验收。

## ADR-083 · 租户管理员敏感数据读取撤权一致性

邀请邮箱、组织人员列表及组织资源分配属于敏感组织信息，当前统一使用 `identity/tenant-admin-read.ts` 的单事务 REPEATABLE READ + `tenant_members FOR SHARE` 管理员核验。不依赖 HTTP 早期身份检查，不复用 UI 缓存角色。访问权在提交撤销后不可再获取；并发撤权发生于读取开始但未获得锁时允许以 40001/403 fail closed，而非在新连接里根据旧权限返回原文。邀请列表不输出一次性 bearer token 或 SHA-256 digest；创建/撤销仍走受锁保护的正式组织命令。应继续审查公开注册关闭、邀请频率限制、接收邮箱验证、审计与日志、边界安全和目标 QNAP/HTTPS 生产部署。

## ADR-084 · AI 模型管理的凭据读取与授权原子性

管理员模型提供商/模型列表及目录、模型测试凭据现在只从当前 `users.is_system_admin` 授权事务的同一 DbClient 读取，`FOR SHARE` 锁使并发撤权与读取互斥，避免 HTTP 旧预检。外部目录发现、文本/结构化测试在事务结束后执行，不持有敏感权限数据库锁等待云端超时。模型测试的 30 秒计费调用冷却与凭据获取在同一事务；列表只展示公开字段及密钥存在性，不返回解密 Key。已开始的真实网络出站仍需要外部供应商侧密钥吊销与出站防火墙才能即时中断，生产发布前必须进一步演练此边界与 SSRF DNS、日志、预算和密钥轮换。

## ADR-085 · 系统 AI 模型管理命令原子授权与审计

供应商、模型创建/修改/删除、批量导入和模型连通性冷却全部在 `identity/platform-model-commands.ts` 中通过现有 `systemAdminTransaction` 完成。权限检查先于请求体 Zod 校验，以免非管理员通过 400/403 差异探测管理字段；一笔事务内记录正确的 `system_audit_entries`，任何失败都不可留成功审计。API Key 加密存储，管理响应/审计只含非秘密元数据；模型目录/推理网络调用仍在提交后才开始，受单一 `model-egress.ts` 的 DNS/SSRF 安全传输约束。生产外部模型撤权后在途调用、供应商费用、值班告警及日志取证须单独验证。

## ADR-086 · 私有 Outbox 压力告警只读隔离

Outbox Doctor 的单一查询仅使用未处理/claim/重试/死信时间和计数字段，不选择聊天原文、prompt、密钥、错误堆栈或事件 payload。活动续期模型调用不被误报为未领取积压；已过期的 claim 和当前待重试压力单独报警，所有指标缺值都返回错误码及非零退出。告警观察阈值与正式租约协议分离，Doctor 绝不自动修改重试状态；人工处理死信仍需当前 Owner/项目权限和正式 Core 授权重放。外部值班通知、抖动去重、数据库瞬断及 Worker 终止故障恢复演练仍是生产准入限制。
