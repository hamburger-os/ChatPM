# 安全、隐私、性能与运行治理

## 权限模型
支持组织/租户、项目、成员角色和可单独授权的管理员操作。每次查询和命令都在服务器端验证租户、项目、角色及对象所属关系。群聊内容、附件索引、AI 引用遵守同一数据作用域。

## AI 特有风险
- **提示注入**：聊天消息与文档只是数据，不得覆盖平台策略；模型工具不开放原始数据库操作。
- **越权与误操作**：结构化候选必须先经策略与领域命令验证，高影响操作由人审查。
- **隐私**：定义模型供应商数据传输策略、密钥保管、敏感数据处理、数据留存与删除流程；不可默认把业务对话发给未经授权的第三方。
- **幻觉**：关键状态只来自正式记录，不确定内容需标识或询问，不作为确定结论对外发布。

## 运维与可靠性
任务处理至少一次，出错重试、隔离队列、人工重放；设置队列滞留和失败告警、模型预算、请求超时、速率限制、日志脱敏及备份恢复。

## 建议监控指标
消息入库/推送延迟、AI 候选接受率、误提取修正率、提醒重复率、逾期无人响应时长、报告引用缺失率、模型用量和成本、队列失败及重试。

## 非功能基线
MVP 先定义可实际测量的性能和可靠性目标，进行负载、数据恢复和权限测试；不在缺乏流量依据时承诺虚构的 SLA 或吞吐数字。

## 默认安全决策
未获组织管理员明确许可时，业务对话不出站传送给第三方模型；未配置模型应提示需要启用，不做伪分析。模型提供商凭证仅保存在服务端，供应商访问、隐私范围和费用预算记录为租户策略。所有数据通过项目范围过滤后才能用于模型上下文。

## MVP 安全限制
会话 HttpOnly、Origin 校验、项目成员权限、模型 opt-in、基础请求限速已实现；仍需生产环境 HTTPS/可信代理部署、分布式限速、权限与提示注入集成测试、数据删除/留存、预算和外部供应商治理，未经上述验证不可上线敏感项目。

## 异步与模型安全补充
隔离事件仅项目 owner 可通过 API 查看和重放，并强制项目作用域、事件状态和审计。处理错误不能在数据库中保留异常原文、私密信息或模型输出。项目模型每日请求数限额不等于 Token 费用预算；生产发布仍需数据隐私、完整攻击测试、删除和备份恢复演练。

诊断统计端点同样需要 owner 权限，避免成员通过失败数推断其他项目的操作；队列监控当前为按需查询界面，尚无主动外部报警。
## 会话与项目隔离约束

- 创建项目时明确提供所属租户，必须检查操作者具备该租户管理员身份。
- 每个会话由带 JTI 的签名令牌与服务端 sessions 表共同校验；退出登录撤销会话。后续仍需补齐管理员全设备撤销和定期清理。
- 项目 Owner 可删除普通项目成员；权限检查必须每次访问时进行，不应缓存撤销前的角色。
- 任务、证据和消息的相互引用必须保持项目归属一致，数据库使用组合外键实现最后一道约束。
- SaaS 的组织策略、模型本地化、完整数据删除和备份恢复仍属生产验收缺口。

项目级授权校验同时要求有效的 `project_members` 与对应租户的 `tenant_members`，防止租户成员关系撤销后仍因残留项目成员记录获得访问资格。跨项目来源引用由复合外键独立约束。

## 成员撤销与任务关系

移除普通项目成员前必须先处理其未完成任务；否则拒绝移除（HTTP 409），防止持续催办已无权访问的用户。移除时对成员关系加数据库行锁，任务创建和重新指派对同一成员关系加 Key Share 锁，避免撤销与新指派并发时产生悬空业务负责人。已完成任务保留历史负责人记录。
