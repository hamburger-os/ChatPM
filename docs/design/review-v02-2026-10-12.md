# ChatPM v0.2 · 第二阶段全量 /review

**审查日期：2026-10-12。** 基线：已合并的 #3（`main`）；范围：PR #7 涉及的 API、Web、Worker、核心模块、PostgreSQL Schema、迁移器、单元/集成测试、CI 与产品/社区文档。

## 结论与边界

推荐保留 **模块化单体 + Fastify API + 独立 Worker + PostgreSQL** 的简洁设计，不引入微服务、Redis 序号源或多自治 Agent。v0.2 在 v0.1 事实可靠性基础上增加可恢复异步事件、受控澄清和可复现工程门禁，适合作为**实验性迭代**评审；不等于可处理真实企业敏感数据的生产验收。

## 安全和设计权衡

1. 正式任务、风险及负责人/期限的修改仍必须经过后端授权，不依靠 Prompt 决定权限；AI 回复只作为可追踪证据。
2. 每项目每日请求限制是**模型调用次数限制**，不是金额或 token 费用阈值。达到上限时事件进入次日队列，不因配额耗尽而判为死信。
3. PostgreSQL outbox 仍是至少一次处理；外部 AI 接口没有跨数据库 exactly-once 语义，靠唯一消息/候选来源防止重复正式写入。
4. 同项目消息写入串行化和单体 API 是当前体量下的合理简单策略；吞吐瓶颈没有测量前不推入 Kafka 或拆微服务。
5. `schema_migrations` 在单库中互斥校验版本，禁止修改已发布的 migration 文件，下一版本只新增文件。

## 可复核 CI 项目

- TypeScript strict 与核心策略单元测试
- 从零迁移 + 第二次重复迁移
- 真正 PostgreSQL 下 8 次错误/退避/死信、额度耗尽、崩溃遗留租约、新旧 claim token 防覆盖
- Mock Model 下带 ID 的多轮澄清、回答幂等、跨项目来源限制、日额度、正式任务不可自动修改
- HTTP + PostgreSQL 下成员越权、审批乐观锁、消息排序、负责人审批澄清日期、死信重放 RBAC、报告全量统计和发布后不变性
- Next.js 构建 + docs-sync 中英成对/链接门禁

**注**：是否全绿以 PR #7 当前最新 SHA 的 GitHub Actions 结果为准。首次测试发现并修复了前端 JSX 缺括号、PostgreSQL 微秒时间戳与 JS 毫秒 Date 的 lease 比较不匹配、测试在新增任务前提前取统计基线等问题。

## 验收决策

仅当 PR #7 最新提交的 Product verification + Documentation governance 都为成功且无阻断审查问题时，**可合并为 v0.2 实验性 MVP**；未完成生产项目继续在 Issue #6 与后续里程碑中跟踪。禁止用 CI 全绿声称“所有生产需求已实现”。

**后续审查补充**：Outbox 采用 UUID `claim_token` 实施领取权比较，防止 PostgreSQL 微秒时间戳在 JavaScript 毫秒转换后导致回写失败；已增加旧租约回写不生效的数据库回归。项目 owner 可查看队列积压、隔离数、模型错误数和最老未完成事件。网页支持在审批候选时修正模型提出的截止日期。
