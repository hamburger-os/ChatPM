# ChatPM v0.1 全量代码审查（/review）

**日期：2026-10-12**  
**范围**：PR #2 中的 API、Web、Worker、SQL Schema、核心规则、测试、CI 与相关文档。  
**结论：基础 MVP 可作为实验性版本合并；不符合生产发布门槛。**

## 架构和实现的审查结论

| 检查项 | 结论 | 支撑 |
|---|---|---|
| 模块化和扩展性 | 有条件通过 | Web/API/Worker 分进程，PostgreSQL 为唯一事实源；API 与 Worker 的业务职责仍需进一步按模块分离 |
| 消息与任务一致性 | 通过 MVP 验证 | 消息采用项目级 nonce 去重；任务采用 version 乐观并发；候选任务审批具有唯一来源约束 |
| 权限与隐私 | 通过基础验证 | API 以项目成员关系判权，审批/报告仅负责人可操作，AI 出站需项目负责人明确启用 |
| AI 安全 | 有条件通过 | JSON Schema 结构化提取，正式记录必须人工确认；外部模型真实输出、安全性和费用尚未完成系统化评测 |
| 主动跟进 | 有条件通过 | 持久化 FollowUpPlan、工作时间与任务版本复查、站内提醒；无独立死信管理和节假日配置 |
| 报告与来源 | 有条件通过 | 报告依据任务/风险当前状态并附 ID；尚不能复原历史周期的精确进度基线 |
| 前端与用户体验 | 通过基础功能构建 | 登录、项目群聊、成员、任务和候选、报告页面；仅轮询，没有附件或实时推送 |
| 文档同步 | 通过机械检查 | 中文设计、AI 文档、社区中英双语及 GitHub Actions 门禁均已维护 |

## 审查过程中已修复
1. TypeScript 异常处理对 unknown 类型的不安全使用。
2. 空请求体错误设置 JSON Content-Type，导致发布报告的 API 返回 400。
3. 任务负责人与截止时间缺乏可操作界面，补充负责人选择、任务计划更新及版本校验。
4. 聊天消息历史初始化和增量游标处理不完善，改为最近消息加载、随后按序号增量补拉。
5. 编辑截止时间误用 UTC 值作为浏览器本地输入，改为按本地显示后再提交标准 UTC 时间。
6. AI 缺少具体澄清追问且高频提示可能刷屏，改为最多两个缺失字段问题、10 分钟同类提示冷却；候选不会因冷却丢失。
7. 扩展 API 集成冒烟测试覆盖跨项目访问、成员权限、重复候选确认、版本冲突与持久化跟进。

## 验证方式
PR CI 执行 Node 22：TypeScript strict、独立单元测试、PostgreSQL 迁移、API HTTP/真实 PostgreSQL 冒烟测试、Next.js 构建；文档 CI 检查链接、Skill 元数据、中英文档配对和改动同步。是否通过以**对应 PR 最新提交的 GitHub Actions**为准。

## 未通过生产审查的项目
- 真实模型集成、误提取率/提示注入与费用上限。
- 完整的消息系统实时推送、附件安全、数据删除/隐私留存。
- 多租户高并发下的压力测试、Outbox 死信监控、精细化审批审计。
- 自动升级和项目级工作日历、独立知识库、对接企业即时通讯。
- 依赖锁文件、版本化数据库迁移策略、可恢复的全量部署与备份流程。

## 合并约束
本 PR 若最新 CI 全绿可合并为 **v0.1 实验性 MVP**。不得宣称实现了《设计方案》中的全部 P1/P2 功能，更不得作为企业数据的正式生产环境。后续每个里程碑继续使用 docs-sync、独立 PR 与 /review 审核。
