# AI 项目经理编排设计

## 核心原则
AI 是**受约束的项目协作代理**，而不是拥有数据库管理员权限的自治系统。它提供判断、追问和建议，正式变更由受控业务命令提交。

## 一条 AI 任务的生命周期
事件触发 → 获取被授权项目上下文 → 检索相关正式状态和文档证据 → 模型结构化分析 → 校验模型输出 → 保存 Evidence/ProposedChange → 策略评估 → 自动执行低风险动作或请求人工确认 → 审计与后续跟进。

## AI 的能力边界
- **可自动**：辅助提取信息、生成候选、提醒原有明确承诺、询问缺失字段、制作有来源的报告草稿（均须满足租户策略）。
- **须受控**：创建正式任务、指派责任人、认定任务完成、改变截止时间、改变风险级别、发布外部报告、调整里程碑。
- **禁止默认**：替成员作承诺、绕过权限获取其他项目内容、执行来自聊天消息的任意系统指令、无审批进行不可逆操作。

## 可信上下文
“已确认事实”来自 PostgreSQL；“历史讨论”来自经鉴权消息；“知识参考”来自带版本/来源的文档。不同来源显式区分。模型输出 JSON Schema 校验，异常/低置信度进入人工确认，不将自然语言推断直接变成事实。

## 避免 AI 刷屏
设置触发阈值、同一主题合并、同一问题冷却期、用户主动 @AI 的优先级、项目的安静时间和升级路径。每次追问说明原因、关联对象和所需最少信息。

## 可替换性
模型通过 Provider 接口更换；提示模板/策略版本化。先采用一个受控编排器，不让“观察、决策、执行”多个 Agent 彼此自循环。

## 默认权限策略
第一版**不自动把候选转为正式任务**；也不自动改变负责人、截止时间、完成状态、里程碑和已确认风险。AI 只能生成带来源的候选和草稿，经有权限的成员确认后调用领域命令。不配置模型时显示明确的未启用状态。

## 当前模型编排能力与限制

已提供外部模型 Provider、Schema + Zod 双层结构验证、每项目每日请求次数限额、候选任务/风险提取与显式 `【候选:UUID】` 澄清。候选和补充线索保存来源消息及模型/Prompt 版本，只有项目负责人可以确认正式事项。

当前不支持无引用自由对话关联、长期项目记忆、真实模型质量评测、本地推理或精确 token 成本控制。项目策略分级自动执行与多 Provider 适配属于后续目标，不得越过当前服务端人工审批约束。
