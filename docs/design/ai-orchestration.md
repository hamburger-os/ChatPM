# AI 项目经理编排设计

## 核心原则
AI 是**受约束的项目协作代理**，而不是拥有数据库管理员权限的自治系统。它提供判断、追问和建议，正式变更由受控业务命令提交。

## 一条 AI 任务的生命周期
事件触发 → 获取被授权项目上下文 → 检索相关正式状态和文档证据 → 模型结构化分析 → 校验模型输出 → 保存 Evidence/ProposedChange → 策略评估 → 自动执行低风险动作或请求人工确认 → 审计与后续跟进。

## AI 的能力边界
- **可自动**：辅助提取信息、生成候选、提醒原有明确承诺、询问缺失字段、制作有来源的报告草稿（均须满足租户策略）。
- **须受控**：创建正式任务、指派责任人、认定任务完成、改变截止时间、改变风险级别、发布外部报告、调整里程碑。
- **禁止默认**：替成员作承诺、绕过权限获取其他项目内容、执行来自聊天消息的任意系统指令、无审批进行不可逆操作。

## 可信上下文
“已确认事实”来自 PostgreSQL；“历史讨论”来自经鉴权消息；“知识参考”来自带版本/来源的文档。不同来源显式区分。模型输出 JSON Schema 校验，异常/低置信度进入人工确认，不将自然语言推断直接变成事实。

## 避免 AI 刷屏
设置触发阈值、同一主题合并、同一问题冷却期、用户主动 @AI 的优先级、项目的安静时间和升级路径。每次追问说明原因、关联对象和所需最少信息。

## 可替换性
模型通过 Provider 接口更换；提示模板/策略版本化。先采用一个受控编排器，不让“观察、决策、执行”多个 Agent 彼此自循环。

## 默认权限策略
第一版**不自动把候选转为正式任务**；也不自动改变负责人、截止时间、完成状态、里程碑和已确认风险。AI 只能生成带来源的候选和草稿，经有权限的成员确认后调用领域命令。不配置模型时显示明确的未启用状态。

## 当前模型编排能力与限制

已提供外部模型 Provider、Schema + Zod 双层结构验证、每项目每日请求次数限额、候选任务/风险提取与显式 `【候选:UUID】` 澄清。候选和补充线索保存来源消息及模型/Prompt 版本，只有项目负责人可以确认正式事项。

当前不支持无引用自由对话关联、长期项目记忆、真实模型质量评测、本地推理或精确 token 成本控制。项目策略分级自动执行、提供商专有协议和实际本地模型兼容性验收属于后续目标，不得越过当前服务端人工审批约束。

## 可配置模型传输与边界（ADR-019）

- **目标**：部署者通过服务端环境配置 OpenAI、DeepSeek 或其它符合已实现协议的模型，不让供应商选择渗透业务审批流程。
- **设计**：保留一个受控 LLMProvider 和原有请求配额；独立传输实现支持 `responses`（JSON Schema）与 `chat-completions`（JSON Object + Zod）。四个部署变量：`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_STYLE`。不维护旧 `OPENAI_*` 兼容层。
- **数据流**：Owner 授权启用 → Worker → 预留项目 UTC 日额度 → 配置的单一模型端点 → 结构化校验 → 有来源的候选或澄清 → Owner 审批。不得直接提交正式工作记录。
- **失败与安全**：配置 URL 仅由部署管理员控制；仅允许绝对合法 HTTP(S) URL，外部必须 HTTPS；密钥不能传入 Web、日志或审计正文；非 2xx、超时、拒答、截断、非 JSON、类型错误立即失败，不自动无提示切换服务商。
- **边界及取舍**：不引入通用 AI Gateway、多厂商 SDK、数据表或密钥管理 UI。HTTP 本机推理仅供可信部署环境，容器需显式设置可达的内部地址。未完成真实模型质量、费用、隐私和生产安全验收。
- **验收**：两种协议模拟请求/回复、失败模式及 URL/Key 配置测试，数据库集成的日额度与重放保持不变，中英文部署指南和 Docker 变量同步。
