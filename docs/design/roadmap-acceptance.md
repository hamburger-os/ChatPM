# 分阶段交付与验收

**状态：设计基线已审查（尚未实施）。**

| 阶段 | 交付重点 | 验收依据 |
|---|---|---|
| 0 · 设计与规范（本次） | 四层文档、Agent 规则、docs-sync、ADR、CI 门禁 | 文档审查通过，目录/链接/中英配对完整 |
| 1 · 协作基础 | 身份权限、项目、房间、消息持久化、在线补拉 | 成员只能看授权项目，断线重连消息不丢 |
| 2 · AI 可信提取 | 模型接口、候选任务/风险、原始引用、授权确认 | AI 不直接修改正式状态，确认/冲突可追溯 |
| 3 · 主动跟进 | 持久计划、幂等提醒、静默及升级 | 已完成任务不催办，重复触发不重复发送 |
| 4 · 知识与汇报 | 文件索引、周/月报草稿、报告来源 | 数字可核对、引用可追溯、未知项不编造 |
| 5 · 生态扩展（后续） | 多模型、外部通知/IM、复杂仪表盘 | 新渠道不破坏领域状态与权限边界 |

## 第一版端到端验收案例
1. 张工在聊天室明确承诺周五完成接口；AI 提出带消息证据的候选任务。
2. 负责人确认任务，系统保存负责人、期限和来源。
3. 张工反馈“测试环境未好”，AI 标记待确认阻塞并询问环境负责人与时间。
4. 依赖风险经确认后进入风险台账；到期提醒遵守项目工作时间。
5. 无论同一事件重复投递多少次，都不会重复生成任务或重复催办。
6. 周报按真实任务状态说明实际进度、阻塞及下周计划，有证据链接。
7. 无权限成员既不能读取其他项目，也无法让 AI 代其执行操作。

## 设计审查与正式开发门槛
负责人审阅核心设计、审批边界、隐私/成本和提醒策略后确认；再启动对应阶段代码。任何新模块先有中文方案与验收口径，实施后通过 docs-sync 对齐。

已提供项目成员/聊天、任务审批、AI 单消息候选提取、站内提醒和快照报告的代码。计划中的 WebSocket、知识库、文件索引、风险升级、跨消息 AI、真实历史基线仍未完成，详见 [实施状态](implementation-status.md)。是否可运行和合并以 CI/集成验证为准，不能用文件存在代替验收。
