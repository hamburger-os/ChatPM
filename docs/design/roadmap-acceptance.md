# 项目路线图与交付验收

**目标用户：** 各类项目团队。**部署目标：** 官方 SaaS + 自部署，同一核心。**许可证：** Apache-2.0。**模型策略：** 云端与本地模型均需支持。**执行权限：** 服务端按项目策略分级，正式承诺不能由 LLM 擅自改写。

## 交付顺序

| 里程碑 | 内容 | 完成条件 |
|---|---|---|
| 核心可靠性 | 明确租户、会话撤销、成员权限、可恢复事件、工作日调度、跨项目数据库约束 | 权限、并发、重启及边界测试通过 |
| AI 协作闭环 | 基于证据的观察、已存在任务关联、缺失信息追问、授权审批、回应追踪 | 一次真实多人讨论可完成提取—确认—跟进—更新 |
| 周期项目汇报 | 历史变化记录、风险清单、负责人审核、报告引用 | 周/月报可还原实际本期变化且来源可点击 |
| 双部署与模型 | Docker 全套部署、云与本地模型可替换、运维、备份恢复 | 自部署和托管环境有相同契约与端到端验证 |
| 社区发布 | 开源治理、安全渠道、社区文档、演示项目、发行及反馈流程 | 陌生开发者可以独立安装、验证和贡献 |

每个里程碑关联具体 GitHub Issues 与可复现测试，不以 PR 数量或功能目录存在作为交付依据。

## 最小端到端验收

1. 成员在群聊明确承诺一项工作，AI 提供带消息来源的候选。
2. 负责人确认责任人、截止时间、完成条件，系统建立正式任务。
3. 后续讨论中的阻塞关联到原任务；AI 不在缺乏证据时擅自改写完成状态。
4. 提醒遵守项目工作时间、成员权限、状态及冷却；重复事件不刷屏。
5. 成员补充进展后 AI 按策略继续追踪，不重复询问已解决的问题。
6. 周报解释实际变化、未完成事项、风险和下一步；对来源无法核查的判断明确标识。
7. 无权限成员不能访问其他项目，模型输出不能获得额外权限。

## 非功能验收

除单元测试，还需完整 API / Web 端到端验证、真实模型评测、异常恢复、日志脱敏、安全与数据生命周期测试及可复现部署。当前交付覆盖见 [实施状态](implementation-status.md)。
