# ChatPM v0.2 · 合并后全仓库 /review（2026-10-12）

## 审查基线与范围

基线：`main@0aa7599`，即 #3、#7 先后合并后的实验性 MVP；审查包括 API、Worker、领域核心、消息、模型请求、数据库、Outbox、报告、前端、CI 和双语文档。本复审修复在 #8，**不代表全部生产需求已完成**。

## 审查结论

总体设计依然合理：PostgreSQL 为唯一正式业务事实源；事务型消息 + Outbox；Fastify API、Next.js Web、单一受控模型 Provider 和独立 Worker；AI 只能存候选/线索，只有授权负责人可批准正式任务和风险。当前规模下无需拆微服务或引入不必要的兼容层/自治 Agent 框架。

| 领域 | 审查证据 / 结论 | 后续风险 |
|---|---|---|
| 身份/租户/RBAC | HTTP 冒烟覆盖项目读写隔离、普通成员不能修改设置/审批/重放；服务端强制 owner 角色 | JWT 无主动撤销机制、成员撤销/跨租户边界测试仍不足 |
| 消息 | `insertMessage` 项目锁、nonce 幂等、并发回归，确保序号与提交顺序一致 | 5 秒轮询、无附件、编辑撤回和在线状态 |
| AI | 严格 JSON Schema + Zod、项目 opt-in、日请求数限额、UUID 显式多轮澄清，人工确认前不修改正式任务 | 缺少真实外部模型评测、敏感信息过滤、Token 费用预算 |
| 事件/提醒 | Outbox UUID 租约、退避、死信隔离、授权重放、项目级诊断；提醒校验最新状态/静默/冷却 | 缺少主动告警、节假日日历和备份恢复演练；外部模型请求无 exactly once 保证 |
| 报告 | 原始按当前事实统计并区分草稿/发布；发现定时 Worker 每 15 秒在生成窗口反复覆写草稿、最多处理前 1000 项目 | **#8 修复**：定时只创建一次、项目键集分页与一分钟扫描，人工仍可刷新草稿；未具备历史进度基线 |
| 迁移和依赖 | npm ci、锁文件、SQL migration 校验和及两次执行回归 | 无已上线环境的备份/恢复、回滚流程与多版本升级演练 |
| 测试/CI | Node 22 strict TS、单测、PG Outbox 和 Mock AI 测试、HTTP 冒烟、Next.js 构建、文档门禁 | 仍需模型质量数据集、实际负载/故障注入及权限变更回归 |

## #8 修复设计和可靠性保证

1. 新增 `generateScheduledReport(db,projectId,kind)`，要求调用方持有数据库事务；获取每项目/类型/周期的事务级 advisory lock，检查同周期是否已有报告。
2. 如果报告存在则不覆写，无论它是可审核草稿还是已发布版本；负责人明确发起 `generateReport` 仍允许重算**未发布草稿**。
3. Worker 项目列表使用主键键集分页读取全量项目，避免大于 1000 个项目时丢失自动报告。
4. 每分钟最多运行一次扫描，且扫描锁只约束报告生成而不阻塞正常聊天任务。
5. `reports.integration.ts` 用真实 PostgreSQL 验证首次创建、定时重试不覆盖、人工刷新、发布不可变和多个 Worker 同时触发最多产生一次。
