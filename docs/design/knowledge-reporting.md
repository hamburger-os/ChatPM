# 项目资料、知识检索与智能汇报

**状态：设计基线已审查；快照周/月报已在实验性 MVP 实施。**

## 知识库定位
资料包括需求、方案、会议纪要、任务交付物、决策和附件。保存原文件、版本、访问权限及必要的文本索引。项目资料经权限过滤后用于回答“为什么如此决策”等问题。

结构化任务/风险/里程碑是权威事实源；全文或向量检索只补充上下文，不直接决定项目完成率或正式风险级别。

## 检索架构
上传 → 格式/大小/恶意文件校验 → 对象存储 → 异步文本提取与分段 → 版本化索引 → 经过项目权限过滤后检索 → 返回来源引用。

初期以 PostgreSQL 结构化查询和全文检索为主，效果不足时添加 pgvector。文件更新或删除后应更新/失效索引，避免旧片段被误用。

## 报告设计
- 周报：本周计划、实际完成、延期/阻塞、风险与决策、下周安排。
- 月报：目标/里程碑变化、阶段成果、风险趋势、资源与重大决策。
- 每个报告保存项目时区、统计时间段、生成时的事实快照、证据链接、生成者及发布状态。
- AI 起草报告但不得编造数字。资料不全时显示“待确认”并链接相应任务。
- 默认先由项目负责人审阅后发布；按租户策略可允许例行内部摘要自动发送。

## 数据质量
报告中明确区分“任务系统记录”与“讨论中推测”；对引用、完成判定、延期时间以及责任归属提供可追溯审查入口。

## 发布权限
第一版报告仅生成带引用的内部草稿，默认不得自动对外发布或发给无项目权限的成员；项目负责人审阅发布属于明确的业务命令。

## v0.1 现状
可按当前项目状态生成或定时形成周/月报草稿，保存周期键、任务/风险 ID，由负责人发布。它不是历史时点快照，不能断言过去每一天的实际进度。附件、全文/向量检索和 AI 文本润色仍是后续工作。

## 报告数据正确性（2026-10-12）
周/月报汇总通过**同一 PostgreSQL SQL 语句读取单个 MVCC 快照**，任务总数、各状态数量、逾期数覆盖整个项目；仅阻塞/逾期明细（200 条）与未关闭风险明细（100 条）限制展示数。报告明确标注快照不是周期历史还原。

同一项目/周期只有一份报告：**草稿允许重新生成覆盖内容**，审核发布后正文不可被后续生成覆盖；AI 定时草稿也遵循同一约束。后续如需历史进度趋势，必须另建状态历史/快照表，不能从当前状态反推。

## v0.2 合并后调度修复（2026-10-12）
自动定时周报/月报与人工重新生成草稿是不同的业务命令。定时命令按项目、类型、周期持有 PostgreSQL 事务级 advisory lock，读取既有报告；若已生成则跳过，避免定时扫描覆盖负责人正在审核的草稿。人工命令仍允许刷新未发布的草稿，已发布报告不可覆盖。Worker 用主键键集分页遍历项目，每分钟检查一次，避免原先只读前 1000 个项目或每 15 秒重复刷新。本阶段没有历史进度快照、补跑窗口或独立调度表，仍需可观测和灾备验证。
