# 第三方集成与长期扩展


## 适配器边界
| 扩展点 | 责任 | 约束 |
|---|---|---|
| 大模型 | 结构化分析与自然语言生成 | 可替换模型，记录模型与模板版本 |
| 通讯渠道 | 站内群聊及未来外部 IM | 保留来源 ID、时序、授权映射 |
| 通知服务 | 站内通知、邮件或企业消息 | 幂等键、偏好、投递追踪 |
| 文档解析 | 不同附件格式提取与分段 | 保留版本及权限，不执行不可信文件 |
| 对象存储 | 附件与内容版本保存 | 租户隔离、权限及删除策略 |

## 接入优先级
优先完成站内群聊和内置提醒，确认 AI 行为正确后，再接飞书/企业微信/钉钉、日历、GitHub 等。第三方渠道可能缺少删除通知、幂等支持或全量历史读取能力，需逐一写适配器限制，不承诺功能完全对等。

## 扩展时保持不变的原则
- 群聊渠道不是任务事实源。
- 外部消息不能授予 AI 新权限。
- 提醒的业务生命周期保存在 PostgreSQL。
- 外部系统的同步冲突必须可审查，不能“最后写入者自动覆盖”所有字段。

## 是否需要微服务？
仅当规模、组织边界或安全隔离证明需要时，以 ADR 记录拆分原因。初期模块接口足以支撑分工与未来迁移。
