# 组织治理、组合/项目集与 AI 统一管理（ADR-023）
 
## 目标与边界
ChatPM 在一个组织内管理部门、项目组合、项目集、项目与多项目共享成员。组织维度表示人和资源，交付维度表示业务投资与工作组织；二者**不能互相替代**。任何项目不强制加入项目集，部门不能伪装成项目集。权限边界始终由 API 服务端验证。
 
## 关系模型
- `tenants` 是组织数据与成员的隔离域；`users` 是可参与多个组织的登录身份。
- `departments` 是组织内的人员单元，成员通过 `department_members` 关联；部门负责人并非全组织管理员。项目可以由一个部门牵头，并跨部门协作。
- `portfolios` 是战略优先级与投资归集，`programs` 是关联项目的协同管理。独立项目允许直接关联组合；加入项目集的项目通过项目集所属组合归集，避免重复计算。
- `project_members` 为聊天及任务访问边界；加入部门并不自动获得项目聊天权限；项目关联不自动提升权限。
- `resource_allocations` 保存参与人员、所属项目、投入比例和日期区间；同一人可跨项目，超配只能作为明确计算结果而非基于聊天猜测。
 
## 权限与管理
系统总管理员仅负责全局配置（特别是 AI 凭据），不默认获得跨组织的聊天/任务数据读取权限；系统权限通过部署管理员受控提升操作授予。组织管理员管理组织成员和治理结构；项目角色包括 owner（项目负责人）、manager（项目管理者）、member（成员）、observer（观察者），每项服务端命令依据角色与对象关系判断。
 
默认成员有项目聊天读写权限；observer 仅查看项目数据。项目负责人/manager 可以创建任务、更新任务计划并审核候选；任务负责人可以更新自己任务的状态。只有 owner 可以管理项目成员、发布报告及开启项目 AI；全局 AI 模型仅系统总管理员管理。禁用成员或移除成员时要重新校验访问，历史审计不可被清除。
 
## AI 配置
使用部署范围 `ai_model_configs` 存储管理员可管理的模型端点与协议。只有选为默认且启用的模型被 Worker 解析；不基于模型名称或域名推断语义能力，传输协议的不同由具名适配逻辑负责。独立 `MODEL_ENCRYPTION_KEY` 加密凭据并明确密钥轮换；服务端从不回显原密钥。普通项目只开关 AI 助手，不提供供应商控制。模型使用和测试必须服从预算、审计与出站限制。
 
## 失败与安全
- 任何资源关联必须验证归属同一组织；数据库组合唯一键和外键是第二道边界。
- 加入项目的人员必须属于组织；管理角色不会透传到其他组织。
- 模型 URL 仅系统管理员能保存，必须使用 HTTPS（可信本机服务 HTTP 例外），禁止 URL 凭据、重定向和不可信私网访问。
- 无默认可用模型时项目开启 AI 必须失败并解释原因；系统管理员仍可关闭全局模型而不修改业务事实。
- 任务和审批保留原有版本/事务/审计/Outbox 机制；不使用模型输出直接提交正式事实。
 
## 取舍
保持现有模块化单体、PostgreSQL、API+Worker，拒绝按部门拆租户、微服务及隐式跨项目授权。为了减少关系含糊，初版一个项目至多一个主项目集，项目集至多归属一个组合；需要多重组合归集时再以明确归集策略复审。
 
## 验收
- 登录成功后业务列表失败不触发登出；401 才进入未登录态。
- 系统管理员可维护模型，项目 owner 无法访问模型密钥管理接口；普通用户不能修改或读取模型管理数据。
- 不同组织不能读取/写入彼此的部门、组合、项目集及关联关系。
- 一个成员可参与多个项目，授权仅随项目成员身份生效；观察者不能发消息或改任务。
- 项目负责人可管理任务、管理者可调整计划、成员仅能修改自己的任务状态；所有变更记录审计。
- 组织/项目结构变更需要集成测试；UI 在无权限时不显示可操作控件。
