# AI 项目经理的治理知识

## 核心原则
AI 可协助收集证据、发现遗漏、追问进展和形成报告，但其概率性推断不能等价于团队承诺。授权、隐私、可追溯和纠错能力是治理基础。

## 四种信息等级
1. 已确认的业务事实：由授权人员/受控系统更新的状态。
2. 来源明确的对话陈述：成员曾这样说，但可能过时或语义含糊。
3. 模型分析与预测：一种有依据的推断，而非承诺。
4. 待确认信息：信息不足、冲突或权限不允许自动处理。

## 常见 AI 风险及对策
- 幻觉与误引用：严格来源关联、结构化校验、不确定时请求确认。
- 提示注入：将来自群聊/附件/外部系统的内容当作数据，不能当作控制指令。
- 过度自动化：根据动作后果分层授权，高影响变更必须有人负责。
- 自动化骚扰：冷却、分组提醒、静默时间、明确撤销/暂停开关。
- 数据泄露：租户范围、模型传输政策、保留/删除、审计和最小权限。
- 偏差和不公正归责：AI 提醒工作事项而非评价成员人格；风险归属须可核查。

## 验证方式
建立匿名或许可的典型项目对话测试集，衡量任务提取的准确性、误指派率、遗漏率、重复催办率、报告来源可核查性和成员纠正成本。每次变更模型和 Prompt 后回归。
