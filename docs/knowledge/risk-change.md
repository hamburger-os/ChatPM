# 风险、问题、变更和决策的通用管理方法

## 必须区分的概念
| 概念 | 含义 | 常见记录 |
|---|---|---|
| 风险 Risk | 尚未发生但可能影响目标的不确定事件 | 影响、可能性、应对、负责人 |
| 问题 Issue | 已经发生、正在阻碍工作 | 事实、紧急性、处理人、截止 |
| 变更 Change | 对范围、期限、质量、成本或责任的修改申请 | 原计划、拟改变、影响、批准 |
| 决策 Decision | 经授权作出的选择 | 选项、理由、确认人、时间 |
| 假设 Assumption | 尚需验证的计划依据 | 来源、验证期限、失效影响 |
| 依赖 Dependency | 某项工作依赖其他交付/决策 | 前置条件、负责人、风险 |

## 推荐工作闭环
发现 → 建立证据 → 明确责任人 → 评估影响 → 选择应对/审批 → 执行 → 核对与关闭。每一阶段可以因项目规模裁剪，不要求无谓增加手续。

## 对 AI 项目经理的启示
聊天中“可能来不及”首先应形成待评估风险，而不是自动推迟里程碑；“明天改到下周”可能是变更申请，而不必然是已批准新日期；“完成开发”也不等于“通过验收”。

## 实践指标
关注未关闭高风险的持续时间、逾期事项被处理的时间、变更审查积压、关键依赖的阻塞时间。避免只统计风险数量，因为主动识别会暂时增加登记数量。
